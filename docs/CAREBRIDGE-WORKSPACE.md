# CareBridge 프론트 실행·구현·검증 안내

기준일: 2026-10-29. 작업 브랜치: `feature/carebridge-transition`.

현재는 그룹별 화면과 합성 데이터로 업무 흐름을 검증하는 초기 구현입니다. 실제 백엔드 보안·저장·AI 동작이 검증된 상태는 아닙니다. 실행 명령과 환경변수는 [README](../README.md)를 따릅니다.

## 모드와 계정

- `npm run dev:carebridge`: 개발 전용 모의 모드. 기본 포트 5174.
- `npm run dev` / `npm run build` / `npm run preview`: 실제 API 모드. 현재 어댑터는 후속 연결 작업이 필요합니다.
- 모의 ID: author, reviewer, reader, successor, admin, pending-author, pending-reader. 비밀번호: demo.
- 로그인 화면에서 “기록이 있는 기관” 또는 “빈 기관부터 시작”을 선택하면 이 브라우저의 합성 기록이 초기화됩니다.
- 기본 합성 기관 초대코드는 CARE2026입니다. 빈 기관부터 생성하면 새 코드가 발급됩니다.
- 모의 데이터는 브라우저 저장소에, 로그인 세션은 메모리에 보관합니다. 미제출 입력은 새로고침·로그아웃 시 사라집니다.
- 실제 admin 자격증명은 이 모의 계정과 별개입니다. 서버가 확인한 테스트 계정 권한을 사용해야 합니다.

## 현재 화면과 모의 동작

| 영역 | 구현 범위 |
|---|---|
| 인증 | 가입 역할 선택·고정, 역할별 메뉴, 로그인·로그아웃, 계정 변경 시 입력·상세 비우기, admin 역할 화면 전환 |
| 그룹 | 생성·초대코드·참여 요청·승인 대기·거절·재요청·승인·퇴출 |
| 관리 권한 이전 | 모의 즉시 이전과 이전 관리자 차단. 실제 요청·수락 절차는 아직 미연동 |
| 대상자 | 이름·선택 메모 등록, 기관 내 순번, 동명이인 구분·검색 |
| 작성 | 원문·모의 초안 생성·초안 수정·제출, 원문 변경 후 재생성, 본인 기록·보류 사유·재제출 |
| 검토 | 기관 제출 목록, 원문·생성본·작성자 최종본 비교, 수정·보류·확정, 버전 충돌 처리 |
| 공개 | 확정 후 수신자 수동 지정·미리보기·별도 공개, 정정 전 차단·철회·이력 |
| 열람 | 지정 공개문만 표시, 열린 상세의 철회 반영, 연결 단절 시 숨김, 복귀 재검증 |
| 공통 | 모바일·데스크톱 대응, 검색·필터·빈 화면·오류, 모달 키보드 이동 |

초안 생성은 합성 문자열이며 실제 번역·음성 전사·의미 검사를 수행하지 않습니다. AI 경고를 표시하는 실제 UI도 후속 연결 대상입니다.

## 확정된 정책과 구현 경계

- 일반 계정의 역할은 고정이며 계정당 작업 그룹 한 개입니다. 현재 모의 저장소는 기관 하나를 다룹니다. 실제 동시 가입·생성·이전 제한은 백엔드에서 검증해야 합니다.
- 기관의 현재 2그룹 관리자는 한 명이며 참여 승인·퇴출·대상자·수신자를 관리합니다.
- 1그룹은 본인 기록만, 3그룹은 본인에게 현재 공개된 내용만 봅니다. 프론트 필터만으로 접근 권한을 보장하지 않습니다.
- 제출 시 원문·생성본·작성자 최종본을 보존합니다. 의도적 재제출은 새 검토 건이며, 같은 요청의 통신 재시도만 requestId로 중복 방지합니다. 이전 제출도 독립적으로 검토합니다.
- 확정은 자동 공개가 아닙니다. 수신자는 수동 선택하며 대상자와 수신자를 자동 연결하지 않습니다.
- 공개문 정정·수신자 변경 시 기존 공개를 차단하고 별도 재공개합니다. 취소했다고 이전 공개가 자동 복원되지 않습니다.
- 퇴출 시 접근은 종료하지만 기존 제출은 남깁니다.
- admin은 지정 QA 범위에서 역할 전환과 자기 제출 검토·확정을 허용합니다. 현재 로컬 역할 전환을 실제 서버 권한으로 간주하지 않습니다.
- AI 경고가 있어도 1그룹 제출과 2그룹 확정·별도 공개를 허용합니다. 경고는 보존하고 업무상 보류와 구분합니다. 현재 모의 화면에는 실제 검사 결과가 없으므로 이 정책의 실서버 동작은 후속 검증이 필요합니다.

미결정 사항: 검사 장애·미실행 시 처리, 초안 생성 실패 시 대체 작성, 관리 권한 이전의 최종 대상 지정 방식, 사용자 이름 변경 시 과거 이력 표시 기준. 현재 코드의 기본 동작을 새 정책 합의로 해석하지 않습니다.

## API 연결 구조와 남은 작업

화면은 `model.ts`의 Gateway를 사용합니다. `gateway.ts`는 모의/실제 모드를 선택하고, `mock.ts`는 합성 시나리오를 제공합니다.

실제 백엔드의 REST API를 우선으로 어댑터를 수정합니다. 임시 경로를 백엔드에 그대로 구현하도록 요구하지 않습니다.

1. 인증·이메일 확인·세션·서버 로그아웃, 고정 역할, admin 서버 역할 전환을 연결합니다.
2. 기관·참여 상태를 먼저 조회하고 활성 기관에서 목록·상세·이벤트를 연결합니다.
3. 역할 reader/viewer 변환, 요청 ID·버전·생성 결과 식별자를 실제 DTO에 맞춥니다.
4. 공개 준비→별도 공개, 정정·철회, 이전 요청→수락·취소, 이력 조회를 연결합니다.
5. 로컬 이벤트와 배포 환경 이벤트를 구분하여 여러 사용자 세션의 즉시 차단을 검증합니다.
6. AI 담당과 별도로 생성 결과·경고 표시·음성 입력·전사 확인을 연결합니다. 검사 결과와 저장·확정 API의 접점은 백엔드 담당과 조율합니다.

현재 개발 프록시는 기존 경로 중심입니다. 새 업무 경로와 인증 요청이 같은 서버로 향하도록 실제 연결 때 보완해야 합니다. 세션 복구·토큰 갱신, 서버 오류·페이지 조회·이벤트 재연결도 실제 계약을 따릅니다.

## 검증

Node 24.22.1에서 다음을 실행합니다.

```sh
npm run lint
npm test
npm run build
```

- `tests/workspace-policy.test.tsx`: 역할·참여 승인·본인 조회·퇴출·권한 이전·대상자 순번·재시도·독립 제출·보류·버전·공개 범위.
- `tests/workspace-ui.test.tsx`: 열린 상세 철회, 늦게 도착한 응답 차단, 초안 재생성 취소, 수신자·공개 단계.
- `tests/workspace-transport.test.tsx`: 주소 미설정·오류 때 모의 대체 금지, 인증 헤더·캐시, 분할 이벤트·시간초과 처리.
- `tests/carebridge.test.tsx`: 보존된 이전 구현의 회귀 테스트. 새 정책 전체를 검증하는 테스트로 간주하지 않습니다.

수동 확인 시 별도 계정/탭으로 작성→제출→검토→확정→공개→열람→철회를 실행하고, 390px 모바일과 데스크톱 화면을 확인합니다. 기존 모의 브라우저 점검과 새 백엔드 통합 검증은 구분합니다.

기존 검증 기록은 자동 테스트 24개와 빌드·린트 통과입니다. 현재 변경의 검증 결과는 실행 로그를 기준으로 확인합니다. 운영 번들에는 모의 계정 토큰·합성 데이터 저장 계층이 포함되지 않는지도 확인합니다. 단위 테스트·빌드 성공을 실제 백엔드/AI 연동 완료로 표시하지 않습니다.
